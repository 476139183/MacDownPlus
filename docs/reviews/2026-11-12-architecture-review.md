# MacDownPlus 深度审查与架构调整

审查基线：`9ae68a5`。范围：自有启动/文件路由、文档编辑保存恢复、预览和原生导出；不漫游第三方 vendor。

审查由状态、路由、渲染三个视角举证，再独立核查主路径、最终消费点和补偿分支。结论以可复现行为为依据；编译通过和进程出现均不视为启动成功。

## 正式问题

### F1 冷启动打开文件崩溃（P1，已修复）

- 触发/操作：应用未运行时，通过 `open -n -a` 或系统打开方式打开 Markdown。
- 主路径：LaunchServices 的 Opened 可先于 Tauri Ready/setup；原 `open_path` 读取未注册的 AppState。
- 证据：原版 stderr 实测为 `state() called before manage()`，随后 `uncaught foreign exception`；原 `src-tauri/src/lib.rs:884–887 → open_path:126`。
- 最终结果/补偿：直接进程终止，没有后备打开路径；用户看到闪退或窗口恢复循环。
- 概率：初始化顺序命中时稳定复现，已实际复现。
- 修复：Builder 阶段注册 OpenRequests；全部文件入口经 Ready 队列和主线程消费；保护早期 Reopen/Exit。
- 验证：真实 cold/warm 系统事件测试，中文及空格路径；实际用户文档只读校验摘要不变。

### F2 保存期间新输入被关闭丢弃（P1，已修复）

- 触发/操作：已有路径的脏文档关闭→Save→保存 pending 时继续输入。
- 主路径/证据：原 `src/main.ts:405–433` 保存旧 capture 后返回 true；`close_document:495–498` 随后删除文档和草稿。
- 最终补偿：虽已重新写入 dirty 草稿，但关闭仍无条件删除，因此无法保护新内容。
- 可见结果/概率：后输入文本未保存且草稿被删；慢保存/IPC 延迟下满足时序即可复现，普通快速保存发生率较低。
- 修复：保存后仍脏则不批准关闭；后端以 approvedText 核对最终文档内容。
- 验证：原函数时序实验由 closeApproved=true/dirty=true 变为 false/true；页面保存并关闭并发输入用例及后端内容许可单测通过。

### F3 退出忽略已批准窗口的新修改和新窗口（P1，已修复）

- 触发/操作：两个文档 Cmd-Q→批准一个→另一个确认框停留时回到已批准窗口编辑，或新建窗口输入→继续批准。
- 主路径/证据：原 `src-tauri/src/lib.rs:200、505–513` 只记录一次窗口队列；最终 `223–229` 不复查就删全部草稿退出。
- 最终补偿：没有编辑冻结、内容版本检查或新窗口纳入机制。
- 可见结果/概率：未经最后确认的新输入丢失；上述交互顺序稳定可达，日常概率中低。
- 修复：QuitReview 每轮重新枚举全部文档，已批准文本发生变化或出现新文档均重新确认；取消撤销退出流程。
- 验证：新修改、新窗口、错误窗口确认、最终全部批准的状态测试。

### F4 并发预览快照使首个请求永久等待（P2，已修复）

- 触发/操作：首个快照回包前连续 Copy HTML，或重叠执行依赖快照的导出。
- 主路径/证据：原 `src/main.ts:394–402、717–719` 仅保存一个 resolver；第二次覆盖第一次，首个超时也不 reject。
- 最终补偿：菜单没有串行门禁，原等待者没有最终结束路径。
- 可见结果/概率：某次复制/导出静默不完成；并发窗口内确定发生。
- 修复：PreviewSnapshots 共享进行中的 Promise；回包、超时、换代都结束请求。复核发现的 ready 等待期间换代也增加了终态检查。
- 验证：双 Copy HTML 都完成；旧代等待期间新代 ready 不发送旧 token。

### F5 偏好窗口获焦时应用级菜单无响应（P2，已修复）

- 触发/操作：Preferences 保持焦点时点击 About、Help、Page Setup。
- 主路径/证据：原 `lib.rs:797–805` 将菜单投到焦点窗口；Preferences 只有偏好通知监听，真正动作消费者仅在 editorUI。
- 最终补偿：没有重派发，因此动作稳定无响应；该焦点条件下确定发生。
- 修复：应用级动作和对话框独立共享，Editor/Preferences 都消费，文档动作仍由文档窗口处理。
- 验证：偏好窗口 About/Help/Page Setup 页面回归通过。

### F6 打印中间文件保留全文（P2，已修复）

- 触发/操作：打印或 PDF 导出后检查应用配置目录。
- 主路径/证据：原 `lib.rs:641–653` 写入持久 print-N.html；native/pdf 最终回调只销毁窗口，没有删除文件。
- 最终补偿：退出仅清理 Drafts，全文副本跨退出保留；每次进入打印链路均会发生。
- 修复：任务窗口销毁、窗口构建失败和下次启动统一删除应用创建的数字编号中间文件。
- 验证：原生自检校验结束后没有 print-*.html 残留，PDF 输出保留。

## 待观察

- **启动快照与 stdin 事件之间的窄竞态**：旧代码先 bootstrap 再监听，逻辑上存在空快照覆盖 stdin 的路径，但缺少真实设备稳定插入该窄时序的实验，故不升级正式问题。新代码已先监听、暂存早到事件，stdin 在移除临时源前落草稿。后续重点是可控延迟的多实例投递实验。
- **异常编码多选的系统交互**：已将各打开入口的失败汇入明确错误显示，单文件失败不阻止后续排队；核心读取失败已有测试，系统文件选择器的负向多选交互尚待人工验证。
- **全部系统拼写/替换、M4 和旧版 macOS**：未完成全面实机矩阵，不以菜单存在或 arm64 编译替代实测。

## 已驳回

- “保存期间新输入已由 dirty 草稿补偿，所以不会丢失”：驳回该补偿假设。旧关闭消费者会立即删除刚写的草稿，F2 已追到最终消费点。
- “编译通过、启动有 PID 就代表应用可用”：不成立。原错误发生在之后的系统文档事件阶段；新增系统事件测试替代此判断。

## 指标与后续重点

- 主审查 8 个候选：6 个正式问题、2 个待观察、无重复正式入池；功能矩阵未测项目另列，不充当缺陷统计。
- R1：启动与关闭退出 3 项；R2：预览/全局菜单/打印清理 3 项；静态边界候选保留待观察。
- 复核补齐 Revert 清理旧草稿和预览换代后的 token 校验，均纳入回归。
- 架构为平级职责模块，没有新增通用服务栈；具体约束见 [设计](../plans/architecture/design.md)。
- 下一轮重点：真实打印机、系统拼写替换、可控启动延迟、多实例 stdin，以及 M4/旧系统验证。

签名回归补充：开启完整 ad-hoc 签名后，系统 dyld 因不同 Team ID 拒绝测试插件。依 Apple 官方 native plug-in entitlement 配置仅放开 library validation，并重新执行真实 bundle 初始化/run 验证。
